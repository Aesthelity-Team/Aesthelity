# RT-02: Routine editor

Implements issue #20 on `rt-02-routine-editor`, based on the completed PD-02 branch so local manual products are available. This branch includes PD-02 commits through `9ddc53e`; review/merge that dependency first if separate feature PRs are required. Team main was synchronized at `fee57c7` before implementation.

## Agreed scope

- Reuse najihsherif/Aesthelity and create a separate RT-02 branch.
- Offer bundled catalog products and locally saved manual products.
- Save routine changes to the existing in-memory `RoutineRepository`. Durable routine persistence belongs to RT-03; routines do not survive app termination in this checkpoint.
- Require a nonblank name and at least one product before saving. Preserve the existing eight-step maximum.

## Behavior

Home → Manage routines → Create routine opens the existing creation screen. Add product opens a searchable picker with separate bundled catalog/manual sections. It shows product names, brands, provenance, basic ingredients, list completeness, and expandable ingredient details/warnings. Partial/unavailable catalog lists and unresolved manual ingredients remain explicit. No safety assessment is inferred from selection or normalization.

The same picker is used for editing. Both editors allow moving steps up/down and require confirmation before removing a product. Keep product cancels removal. Add, remove, and reorder maintain contiguous numbering while preserving each step UUID, source-specific product reference, ingredient order, duplicates within labels, and normalization metadata. Selecting the same product twice is blocked by reference, while different products with identical names remain selectable. Existing demo steps without product metadata remain visible with an explicit ingredient-information-unavailable message; references are not guessed from titles.

`RoutineProductReference` distinguishes bundled catalog IDs from manual product UUIDs. `RoutineProductSnapshot` retains selected product information for an in-memory routine. This is a snapshot, not a live link or a persistence schema; later manual-product edits do not silently change an existing routine step. RT-03 must agree on durable reference/snapshot encoding and missing-product behavior.

Creating and editing use shared validation. Save is blocked for blank names, empty steps, or more than eight steps; messages appear beside Save. Names are trimmed on save. Draft operations do not mutate the repository until Save; leaving an editor discards unsaved edits. The home edit callback now updates the shared repository instead of discarding the returned record. Existing scripted Home routine cards remain demo presentations; this task does not implement RT-03 or a live routine analysis/dashboard.

The separate Reorder steps screen also uses the shared move operation so it no longer regenerates IDs. Reordering its draft is applied only when confirmed, and the parent editor still requires Save changes to update the repository.
