# QA-02 integration verification

Issue [#40](https://github.com/Aesthelity-Team/Aesthelity/issues/40) covers the journey from first use through profile setup, routine creation, and analysis. This work builds on AN-06 at commit `358269e`, including the review corrections in [PR #122](https://github.com/Aesthelity-Team/Aesthelity/pull/122).

## Reproducible acceptance flows

### Completed profile

1. Launch with first-use state and empty isolated routines.
2. Choose Get Started, select Dry and Barrier repair, and continue.
3. Open Profile and verify the completed status and selected values.
4. Return Home and create a routine with Retinol Night Serum and Exfoliating Treatment from the bundled catalog.
5. Verify the saved name and selected products on Routine analysis.
6. Verify suggested layering and the multiple-treatment caution.
7. Run personal analysis. An unavailable protected endpoint must show an error and keep the routine available for retry.
8. Retry, return Home, and relaunch. Verify the completed profile, routine name, and both product steps persist.
9. In the configured manual environment, run authenticated HTTPS analysis and inspect the returned findings and incomplete coverage.

### Skipped profile

1. Launch with first-use state and empty isolated routines.
2. Enter profile choices and use Skip.
3. Verify Profile reports skipped/incomplete, with no skin type or concerns carried over from the draft.
4. Create a routine containing Gentle Gel Cleanser and Incomplete Mask Demo.
5. Verify Routine analysis retains the product order and displays uncertain layering.
6. Exercise analysis failure and retry without a complete profile.
7. Relaunch and verify the skipped state and both routine steps persist.
8. In the configured manual environment, run authenticated analysis and verify incomplete coverage and the explanation of unknown allergy status.

### Error and recovery

1. Open personal analysis for an existing isolated QA routine.
2. Run while the protected backend is unavailable.
3. Verify an actionable error, an enabled retry action, and the retained routine inputs.
4. Restore the backend and retry the same routine.
5. Verify the result renders and the routine remains available.

Personal analysis currently sends unknown recorded-allergy status for both profile paths. Avoidance preferences remain separate from recorded allergies. An incomplete or unknown result is expected even with a completed profile. An unavailable backend must never produce the “No recorded conflicts” card.

## Test isolation

`IntegrationJourneyUITests` uses the existing `--pf01-ui-testing` profile/defaults suite and `--rt02-ui-testing` routine store. Reset flags affect those isolated stores. Returning-user checks relaunch with the same flags and omit resets.

Automated UI tests use the bundled fictional catalog and an empty `AESTHELITY_PROTECTED_API_BASE_URL`. They exercise the production failure presentation without Firebase credentials, shared database writes, or live model requests.

The loopback HTTP tests use in-memory data, an injected token verifier, and deterministic providers. Normalization-to-analysis checks now import the checked-out engine directly. A missing historical `origin/99-ai-analysis-engine` ref previously skipped six checks and could hide a regression.

Manual HTTPS verification uses the local backend and the simulator's existing signed-in account, with synthetic profile/routine inputs in the isolated stores. Analysis reads approved references and submits fictional ingredient inputs. Account Save/Load actions are outside these acceptance flows.

## Commands

Run from the QA branch with Xcode selected through `DEVELOPER_DIR`.

```sh
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
xcodebuild test \
  -project Aesthelity/Aesthelity.xcodeproj -scheme Aesthelity \
  -destination "id=<IOS_27_SIMULATOR_UDID>" \
  -derivedDataPath /private/tmp/aesthelity-qa02-derived \
  -parallel-testing-enabled NO \
  -only-testing:AesthelityUITests/IntegrationJourneyUITests \
  -resultBundlePath /private/tmp/aesthelity-qa02-journeys.xcresult \
  CODE_SIGN_IDENTITY=- AESTHELITY_PROTECTED_API_BASE_URL=
```

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m unittest discover -s tests/backend -v
.venv/bin/python tests/backend/demo_catalog.py
```
