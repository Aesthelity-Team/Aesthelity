# PF-01: Optional skin profile

Setup uses a typed `SkinProfileDraft` with no preselected skin type or concerns. Each avoided ingredient is a separate editable entry. Continue validates the draft, normalizes valid entries with DATA-02, writes the profile, and then enters the app. Skip saves an empty profile with an explicit `skipped` status before continuing.

## Storage and state

`AesthelityApp` owns one `SkinProfileStore` and shares it with setup and the Profile tab. The store loads `Application Support/SkinProfile/profile.json` and supports schema version 1. Writes are atomic and use complete file protection. Observable state changes only after a successful write.

An unreadable or unsupported file remains intact until the user explicitly saves another profile. The app displays the load error. A failed save keeps setup open and preserves the user's draft.

Returning users keep their first-use flag and load the saved profile. The Profile tab shows the saved skin type, concerns, ingredients, normalization warnings, and setup status. Edit skin profile opens a separate setup sheet with those saved choices. Back cancels edits without changing the saved profile or first-use state.

Avoidance preferences remain separate from `DemoProfile.recordedAllergens`; this feature does not change the DATA-01 analysis fixtures or rules.

## Ingredient behavior

Entries retain typed text during editing and validation errors. Successful submission strips invisible Unicode format characters and surrounding whitespace. Exact aliases deduplicate by canonical ID; unresolved entries deduplicate by the normalizer's text key. Unknown or ambiguous ingredients remain explicit preferences with warnings. A suggested ingredient becomes a confident match only after the user chooses its canonical name.

All profile fields are optional. Submitting an empty profile is completed setup; choosing Skip is explicitly incomplete setup. Removing a blank entry allows submission without creating a preference.

## Acceptance verification

| PF-01 criterion | Automated evidence |
|---|---|
| Valid choices appear accurately in the summary | `testCompleteProfileSuggestionsSummaryAndRelaunch` checks skin type, concerns, canonical aliases, confirmed suggestions, and an unresolved ingredient. |
| Skip creates an explicitly incomplete profile | `testSkippedDraftRemainsIncompleteAfterRelaunch` starts with a populated draft, skips, and verifies an empty, incomplete saved profile. |
| Invalid input shows an inline error and retains the entered value | `testInvalidInputIsRetainedAndCanBeCorrected` submits punctuation-only input, checks the error and retained text, corrects it, removes an invalid blank entry, and submits successfully. |
| No personal information is preselected | First-use selection assertions and `testEmptyOptionalProfileCompletesWithoutInventingChoices`. |
| Saved values survive relaunch | Complete and skipped UI tests terminate and relaunch the app without resetting storage. Store tests also reconstruct a store from the same file. |
| Save errors do not publish unsaved values | `failedSaveDoesNotPublishAnUnsavedProfile`. |

The final acceptance run passed all 98 unit tests and four PF-01 UI flows on iPhone 18 Pro with Xcode 27.0. The existing smoke, launch-performance, and launch-configuration checks also passed in the full suite. Test screenshots were inspected for summary accuracy, visible errors, and appearance contrast.

The unit suite includes four persistence tests alongside the existing profile, normalization, catalog, and app tests. The UI suite adds four profile flows and retains the existing smoke, launch-performance, and launch-configuration tests.

UI tests pass `--pf01-ui-testing` to use `PF01UITests/profile.json` and a separate `PF01.UITests` defaults suite. `--pf01-reset-profile` resets only that test storage. Relaunch checks omit the reset argument. Normal app storage is untouched.

Run the suites with the installed Xcode:

```sh
cd Aesthelity
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild test \
  -project Aesthelity.xcodeproj -scheme Aesthelity \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  -only-testing:AesthelityTests -only-testing:AesthelityUITests \
  -parallel-testing-enabled NO
```

## Rollback

The implementation is committed in separate persistence, screen-wiring, and test/documentation checkpoints. Revert dependent checkpoints in reverse order. Preserve local Xcode configuration edits before reverting project-file changes, then restore them. Reverting the code does not delete an existing saved profile file.
